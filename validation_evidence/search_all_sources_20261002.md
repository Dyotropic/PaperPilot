# 三源检索优化与流程验收（2026-10-02）

多源检索的顺序等待、重复请求、翻译、去重及模型加载会增加结果展示前的耗时。本轮优化三源召回和共享流程，并验证受影响的检索、文献库、AI、原文及图谱交互。验证基线为 develop 的 `bc8b74d`；发布状态以仓库提交历史为准。

## 当前改动

| 范围 | 改动及作用 |
| --- | --- |
| 共用流程 | 已启用的三个源之间并行；源内依赖步骤顺序执行。独立会话/错误列表/取消上下文，固定合并顺序。连接复用、翻译合并缓存、等价去重、CE 模型复用。 |
| arXiv | 400 条单页；实际 HTTP 按进程级可取消的 3 秒频控；去掉 SDK 等待和整次查询重复重试，失败页仅重试一次。成功非空查询缓存，保留后页失败前的结果。 |
| Europe PMC | 保留完整摘要的单请求及被引排序；已解析公共字段紧凑缓存、兼容旧缓存。超时透传，失败最多三次，末次不再空等；停止同源后续无效召回。 |
| OpenAlex | 100 条分页、摘要按唯一 W-ID 每批 100 条；明确缺失短缓存，错误不作为缺失缓存。普通查询遵循请求超时。 |
| 联动修复 | 带正式 DOI 的 arXiv URL 仍可下载；复用精确查找编号规范化，支持旧式编号并避免普通 DOI 数字误识别。缩短 CE 冷加载锁范围，使第二排序任务共享加载时仍能及时取消。 |

没有削减召回数量、CE 候选、摘要内容或排序权重。公开接口和数据库字段保持兼容。

## 已验证的业务链路与范围

- 机器人导航、肿瘤免疫、钙钛矿三个中英文课题，使用生产三源适配器连接本地 HTTP 元数据。每源关键词和描述两路召回，汇总去重 1200 篇，真实既有 CPU CE 精排 100 候选，返回 50 篇。
- 连续走 SQLite 新建课题、保存/重复保存、状态筛选、库内 CE 重排，AI 评分、PDF 全文精读及摘要降级、Agent 对话/独立会话，CSV/BibTeX 导出，PDF 下载/缓存/归档/本地导入，缓存引用构图。
- LLM 使用真实 SDK 的本地 JSON/SSE 传输与受控回复；验证协议和交互，不验证云端回答质量。初次三领域下载用例去掉 DOI，后续发现真实联动问题并修复，再以保留 DOI 的钙钛矿完整链路及现代/旧式编号专项用例复验。
- 原生 Flet 完整应用：受限鼠标点击探针后走生产 Agent 检索动作；选中、保存、库内排序及页面切换使用生产回调。替身三源/CE 检查三源重叠与 50 行；另外执行上述真实 API/CE 的部分成功场景。没有声称每个控件都经鼠标逐一操作。
- 原生 PDF 阅读器检查显示、文字层、跳页和窗口恢复；图谱另从实际文献库/受控引用缓存构图，检查三节点、两引用边、三共现边及引用/共现/时间线视图、详情关闭、窗口恢复，截图已查看。
- 边界覆盖：空/无效输入，严格年份/作者/期刊筛选，精确查找与原有身份，403/429/超时/畸形响应，后页失败保留，取消排空和迟到结果，跨检索上下文归属，正/缺失缓存兼容及过期，CE 加载/预测失败和空闲释放、共享加载时第二任务取消。

## 未验证及结果边界

未做付费云端中文翻译/AI 回答质量、所有服务商的完整真实请求、付费出版商下载或订阅推送全流程。三个中英文课题的受控业务流水线不能替代这些实际外部场景。已验证范围内没有发现尚未解决的本次回归；不能宣称所有模块在所有模型、UI、网络条件下完整通过。

本机 100 候选真实 CE 推理仍是主要耗时；本轮模型复用降低重复加载成本，没有改变推理模型或压低候选规模。若进一步优化单次精排，应以相同文献/分数等价验证评估 CPU 线程、批处理或推理后端，避免用变更排序质量换速度。
